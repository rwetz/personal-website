# Ateru: native captures and App Store presentation

Use native iPhone captures for the next asset set. The portfolio's existing
browser captures are temporary real-UI references, not App Store masters.

## Capture originals

- Use the current intended release build on an iPhone or iOS Simulator, with the
  coral-on-black theme, consistent text size and realistic fictional library data.
- Capture Library, a populated title detail, Search with useful results,
  Chronicle, Statistics, and a second genuinely useful supporting view such as
  Habits. Keep only views that are in the submitted build.
- Save original full-resolution PNGs. Transfer as files without messenger
  compression, cropping, device frames or captions. Retain these masters.
- Avoid empty states, loading indicators, debugging controls, personal account
  details and features enabled only through debug access. Wrapped is seasonal;
  do not make it the lead promise for an ordinary launch.

## Proposed visual direction

Six coordinated portrait panels: near-black backgrounds, large rounded white
headlines, coral emphasis, softly lit dark iPhones and one clear benefit per
panel. Keep the first device almost frontal and large enough to read. Reserve
subtle three-quarter angles and overlapping phones for later panels. The UI is
the subject; lighting and hardware should frame it rather than compete with it.

Suggested order: daily library, recording progress, discovery, viewing history,
statistics, then the strongest supporting feature. Write final headlines after
reviewing the actual captures so they describe what is shown.

## Tools

- [Rotato Web](https://app.rotato.app/): recommended for placing real PNGs into
  3D phones, adjusting camera angles and rendering images in a browser, including
  on Windows. Make one consistent lighting/camera setup and reuse it.
- [AppScreens](https://appscreens.com/): a faster complete screenshot-layout
  workflow with device frames, captions and exports in store sizes. Prefer this
  if speed and coordinated resizing matter more than custom 3D direction.

## Export constraints

Apple does **not** require rendered 3D phones. Screenshots must show the app in
use and may include text/image overlays. Device renders are the chosen art
direction. Use the final canvas dimensions required by the current App Store
Connect listing; Apple's accepted large Dynamic Island portrait sizes include
1320 × 2868. Preserve the original screenshot aspect ratio inside the phone and
export opaque PNGs at the final canvas size.

App preview **videos** have separate rules: Apple calls for screen captures of
the app itself, so do not assume a 3D phone marketing animation can be submitted
as an App Store preview.

[Apple screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/),
